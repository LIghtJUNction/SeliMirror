# 验证计划

本文件给出验收条件。实际执行结果另行记录，不能用主机测试代替真机结果。

## 对照版本

- ReSukiSU 当前更名为 BakaSU，固定版本 `896e8981e0ed76ec14d1dcb39ab793438b304886`。
- 目标内核：`Laulan56/android_kernel_xiaomi_sm8150` 的 `miui` 分支，固定版本 `bd65f57d4c36882a5dfd34557e64198516ed392b`。
- 比较三种状态：同一系统的原厂策略；相同系统和策略上的 ReSukiSU；目标 root 环境加载本 KPM。逐项记录差异，不能仅比较一个“通过”图标。
- 记录系统版本、内核构建标识、KernelPatch 版本、原始策略摘要、模块构建摘要和测试 UID。策略文件必须对应正在测试的系统版本。

## 可在主机验证的部分

把字节解析、UID 判断、换行处理和响应边界保留为无内核依赖的短函数。测试直接调用生产代码；不要另写一个“测试版”实现。顺序检查可用少量替身函数记录权限检查、策略转换和真实 SID 登记的调用。主机测试不模拟整个内核。

### access 输入解析

以目标内核的 `sscanf(buf, "%s %s %hu", ...)` 为准。**主机 libc 的 sscanf 不能作为参考实现**：它的正负号及空白处理可能不同。[目标内核 scanf](https://github.com/Laulan56/android_kernel_xiaomi_sm8150/blob/bd65f57d4c36882a5dfd34557e64198516ed392b/lib/vsprintf.c)

表中 `A` 和 `B` 仅代表解析用的两个字符串，不代表有效 SELinux 上下文。解析通过后仍须验证上下文及类权限。

| 输入 | 解析结果 |
|---|---|
| `A B 1` | 成功，类号 1 |
| ` A\tB\n00012 ` | 成功，类号 12 |
| 空串、`A`、`A B`、`A B x` | `-EINVAL` |
| `A B +1`、`A B -1` | `-EINVAL`，无符号转换要求首字符为十进制数字 |
| `A B 12tail` | 成功，类号 12；不要求消耗整个数字字段 |
| `A B 0x10` | 成功，类号 0；使用十进制前缀，不解析十六进制 |
| `A B 1 extra` | 成功，额外字段不影响三项转换 |
| `A B 65535`、`A B 65536`、`A B 65537` | 分别得到 65535、0、1，按 16 位转换 |
| `A B 18446744073709551616` | 得到 0；大整数保留无符号溢出及低 16 位行为 |
| `A B 1\0tail` | 成功，NUL 后内容不参与解析 |
| `A\0 B 1` | `-EINVAL`，没有完整三项 |

增加空白字节集合测试：`0x09..0x0D`、`0x20`、**`0xA0`** 均是目标内核空白；`0x00` 不是空白。测试高位字节时使用无符号值，避免数组下标越界。[目标内核字符表](https://github.com/Laulan56/android_kernel_xiaomi_sm8150/blob/bd65f57d4c36882a5dfd34557e64198516ed392b/lib/ctype.c)

检查输入长度为 0、最大允许值，以及字符串没有额外可读尾字节的情况。用地址与未定义行为检查器检查越界、整数溢出和写入只读输入。

### 返回缓冲区

- 输入字节数和可用输出容量是两个不同值。目标事务容量为 `SIMPLE_TRANSACTION_LIMIT = PAGE_SIZE - sizeof(ssize_t)`；4 KiB 页、arm64 时为 4088。最大输入为容量减 1，给 NUL 留位置。
- 用短输入和较长响应验证，例如输入 `A B 1`，响应包含多个 `ffffffff`。输出不能按输入长度截断，也不能写入仅按输入长度分配的临时区。
- access 返回六个字段：`allowed ffffffff auditallow auditdeny 1 flags`。检查空格、十六进制格式、固定序号 1、实际返回长度及结尾 NUL；返回长度不包含 NUL。
- context 返回规范化上下文，**返回长度包含 NUL**。长度等于事务容量时允许；超过容量返回 `-ERANGE`。
- 在输出区前后放置保护字节，验证最大响应不会越界。
- 内部回调成功返回响应长度；外层 `write()` 成功返回原输入长度。后续 `read()` 获取响应。两者不可混用。

上述容量和外层返回语义来自[事务实现](https://github.com/Laulan56/android_kernel_xiaomi_sm8150/blob/bd65f57d4c36882a5dfd34557e64198516ed392b/fs/libfs.c)及 [selinuxfs](https://github.com/Laulan56/android_kernel_xiaomi_sm8150/blob/bd65f57d4c36882a5dfd34557e64198516ed392b/security/selinux/selinuxfs.c)。同一 FD 第二次写入应保留原生 `-EBUSY`；过大输入保留 `-EFBIG`。

### 权限、UID 和上下文顺序

| 场景 | 期望行为 |
|---|---|
| 原始真实 UID 为 0、9999 | 调用原处理函数 |
| 原始真实 UID 为 10000、99999、100001 | 进入启用后的模块路径；不对 UID 取余 |
| 真实 UID 10000，有效 UID 0 | 仍按真实 UID 处理 |
| 权限拒绝，同时输入无效 | 返回真实权限错误；不解析或登记 SID |
| 私有策略拒绝，真实策略接受 | 返回私有策略错误；不登记该上下文的真实 SID |
| 两个策略均接受 | 私有和真实 SID 独立生成；不能将私有 SID 写入真实凭据 |
| access 源上下文接受，目标上下文拒绝 | 返回目标错误；源上下文此前登记真实 SID 的副作用允许保留 |
| 属性名不是 `current` | 完整调用原函数，包括未知属性名的原始错误 |

不要把权限拒绝统一改成 `-EINVAL`，也不要先调用真实上下文转换，再判断干净策略是否接受。

### current 的换行

设有效上下文为 `C`。分别测试 `C`、`C\n`、`C\0`、空输入、单独换行、NUL 开头和两个末尾换行。对非空且首字节既非 NUL 也非换行的输入，只移除**末尾一个**换行；保留输入的其他字节和原函数的错误。本模块预检将该换行改成 NUL，同时减少长度；随后把已修改缓冲区和已减少长度交给原函数。成功写入 `C\n` 时，底层 current 返回减少一个字节的长度，原函数不能再次缩短。空输入、单独换行和 NUL 开头的输入仍交给原函数完成错误路径。

### 与上游 SID 副作用的细微差异

上游 `ksu_security_context_to_sid()` 先解析备份及真实上下文，再登记 SID。备份解析失败时不会登记真实 SID；备份解析成功后，才可能登记真实 SID。[上游实现](https://github.com/Baka-SU/BakaSU/blob/896e8981e0ed76ec14d1dcb39ab793438b304886/kernel/feature/selinux_hide.c)

- `/context` 与 `/access` **忽略真实策略转换或 SID 登记错误**，按备份策略结果继续；`current` 则要求二者均成功，且备份错误优先。
- 如果备份解析成功，但随后备份 SID 分配失败，上游仍可能登记真实 SID。先完成私有转换、失败即返回的实现会少这一项错误路径副作用。应记录此差异，不宣称在内存耗尽时逐项完全一致。
- 用替身分别注入“私有解析失败”“私有登记失败”“真实转换失败”。验证返回值、调用顺序及每个表的修改，不能只验证成功路径。

## 真机验收

### 加载与策略

1. 确认模块与目标内核构建配置一致。交付中的 `raphael_stock` 参考配置不等于用户正在运行的配置；版本和部分结构偏移检查不能证明全部 ABI 一致。检查每个必需符号解析成功；任何缺失均应使加载失败，回滚后没有仍能进入模块代码的有效回调。KernelPatch 常驻链和入口可能有意保留。
2. 使用来源明确、对应当前系统的干净策略启动，确认上下文验证和权限查询基于该副本。缺失文件、不可解析的损坏/截断二进制应明确失败。其他系统但格式合法的策略可能解析成功，模块不能认证来源或系统版本；这类测试应记录加载结果和查询差异，不能要求一律自动拒绝。禁止把已修改的实时策略当作默认干净基线。
3. 在加载前后记录原生 `enforce`、正常文件访问及当前进程上下文。模块不应扩大真实权限或让正常系统服务失效。
4. 私有策略初始化不能调用会触发全局策略加载、AVC 重置或广播的路径。重复查询应不改变真实策略的规则或加载计数。
5. capture 模式在首次原生策略成功加载后读取其输入二进制；对照上游稍后在添加 root 规则前复制的实时策略。若两者之间存在合法重载或 boolean 修改，记录快照差异，并以经过核对的文件模式基线复核。

### 四个接口

| 接口 | 必测内容 |
|---|---|
| context | 原厂有效上下文、仅 root 修改中存在的上下文、无效 user/role/type/MLS、类型属性充当具体类型、嵌入 NUL、最大长度；逐项比较 errno 和响应字节 |
| access | 有效上下文对、仅实时策略存在的类型、permissive 标志、类型属性规则、条件规则、MLS/角色约束、类号 0 与不存在的类；比较全部六字段 |
| current | 已有合法转换、无效上下文、仅实时策略中的上下文、多线程及被 ptrace 的进程；拒绝后确认真实 SID 没变，成功时确认使用真实 SID |
| status | read 与只读 mmap 内容一致；4.14 晚加载值为 sequence=0、policyload=0、enforcing=1；偏移非 0 或非一页映射为 `-EIO`，可写映射为 `-EPERM`，mprotect 不能获得写权限 |

类号非法不一定让 access 写入失败：解析后应保留目标内核的权限计算结果及错误处理。禁止在解析层添加上游没有的类号有效性要求。

分别以普通应用、隔离应用、第二用户应用和真实 UID 0 执行。权限受限接口必须在原环境中有可比的调用条件；单纯通过 root shell 运行不等于验证普通应用路径。

### 开关、并发和生命周期

1. 开启前打开一个 status FD 并建立映射；开启后重新打开另一个。分别确认旧、新句柄遵守各自打开时的状态。
2. 关闭模块功能后，已经指向副本的 FD 和映射仍应可读。不能提前释放其页面。
3. 并发执行 context/access/current/status 查询，同时切换功能。检查挂起、崩溃、错误 SID、返回数据混杂及内存增长。
4. 本模块支持卸载。验证常驻入口已经关闭、在途模块回调已经结束、链中的模块回调已经移除，旧私有 status FD 与映射仍有效，新打开的 status 回到原生页面。KernelPatch 链/trampoline、已发布入口页和已返回的状态页有意保留到重启；不能以“所有内存已释放、所有原始指令已恢复”为验收条件，也不能只测试卸载命令返回成功。
5. 让加载在每个 hook 安装步骤失败，检查先前安装的模块回调均已移除或关闭，不再能访问卸载后的模块代码。`remove=0` 保留链/trampoline 属于预期行为。功能开关和实际运行状态应准确区分。
6. 加载、控制和卸载管理命令串行执行；并发压力来自普通接口查询。固定版本 KernelPatch 的 `module_control0()` 共用参数存储，不把并发管理调用列为本模块已支持的条件。

### Hunter 6.72

使用同一设备、系统版本、root 设置和 Hunter APK。每轮关闭旧测试进程并重新启动，再记录 SELinux 各子项、完整原始结果及模块状态。至少比较模块关闭、ReSukiSU 开启、KPM 开启三组。只有真实结果支持时，才报告“该配置通过 Hunter 6.72”；不能将编译成功或接口单测当作通过依据。
